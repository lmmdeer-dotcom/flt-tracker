## v1.1 改造：GitHub 同步 → Supabase 免配置云同步（2026-09-03 下午）

用户要「同事打开即用、零配置、保存即自动同步」，GitHub 方案无法实现（写 API 必须带凭据，且 GitHub secret scanning 会自动撤销公开页面内嵌 token）。用户选定 Supabase（注册时用 GitHub 一键登录，region 选 Singapore）。

### Supabase 项目
- Project URL: https://hdjzbqksvrykqcymgccc.supabase.co（ref: hdjzbqksvrykqcymgccc）
- 单表 `flt_rows(tbl text, id text, payload jsonb, updated_at bigint, deleted bool, PK(tbl,id))`，RLS: public_all for all using(true)，grant to anon/authenticated（用户"内部数据无所谓公开"）
- anon key 设计上公开可内嵌页面，是官方用法
- REST 通道验证：GET select、POST upsert（?on_conflict=tbl,id + Prefer: resolution=merge-duplicates,return=minimal）、DELETE 均 204/201 通

### 同步协议（行级，替代 GitHub 整文件）
- 每行 payload = 完整业务行（含 updatedAt）；云端列 updated_at/deleted 冗余
- pull: 分页拉全表（Range-Unit items 循环）→ 每表 applyCloud：云端墓碑物理删本地、云端新行覆盖、本地较新留给上传
- push: buildPushRows 只传「本地比云端新」行 + 「本地墓碑比云端新」的墓碑；成功后 clearUploadedTombs
- **删除必须墓碑**（flt_tombs localStorage 持久化），否则云端旧行会在下次 pull 复活——已改造 delRow/clearTab/saveTemplate空名/clearTemplate/toggleLog/delHabit(级联 checks)/togCheck取消
- 自动同步：saveT→markDirty→debounce 3s syncNow；boot 900ms 自动拉取（ghAuto 开关）；同步串行 _syncBusy
- 设置项保留开关键名 ghAuto/ghPushAuto（存 settings）；ghState/ghLog/ghRepoNm 为 DOM id 沿用

### 冒烟测试（jsdom + 内存 fake supabase）
- 全 PASS：建档→本地新增→云端收到→远端合并→删除墓碑化→不复活→8 视图→主题→pill
